# ripdpi-strategy-core

**Responsibility:** the core RIPDPI desync techniques — the stateless
`DesyncStrategy` implementations (`split`, `disorder`, `fake`, `oob`,
`fake_rst`, `seq_overlap`, `ip_frag`, `multi_disorder`, `tls_rec`,
`tls_rand_rec`) plus the descriptor-only `synack` / `synack_split`
placeholders.
**Layer:** L3 — domain logic.

This crate is the home for the techniques that used to be the
`ripdpi-strategy-registry` `BUILTIN_TECHNIQUES` table and the
`BuiltinTechnique::plan` central `match`. Each technique is now a concrete,
registered strategy: the registry resolves it from its descriptor with no
central edit.

## How a strategy is registered

Each technique contributes one `StrategyStepRegistration` to the
`STRATEGY_STEP_REGISTRATIONS` `linkme` slice from `ripdpi-strategy-trait`,
pairing a static `StrategyStepDescriptor` (id, label, aliases, required tier
and capabilities, parameter metadata) with the `StrategyStepFactory` that
builds it:

- the 10 implemented techniques register a `StrategyStepFactory::Stateless`
  builder, generated by the `core_strategy!` macro;
- `synack` / `synack_split` register `StrategyStepFactory::Unimplemented` —
  the descriptor is published for inventory and capability surfaces, but the
  Tier-3 primitive is not wired through `DesyncMode` yet, so the registry
  materializes a placeholder whose `plan` fails.

`ripdpi-strategy-registry` force-links this crate
(`extern crate ripdpi_strategy_core as _;`) so the slice entries reach the
final binary.

## Dependency direction

**Upstream:** `ripdpi-strategy-trait`, `linkme`. **Downstream:** force-linked
by `ripdpi-strategy-registry`.
