## Context

The fake sender runs synchronously on a connection worker. It uses shared mmap
pages for stream retransmission or raw packets with TCP_REPAIR. The caller
currently receives an opaque I/O result. Helper requests carry byte arrays in
version-three JSON frames with an 8192-byte control limit.

## Goals / Non-Goals

- Goal: repair F1 through F8 with separate fix commits and owning regressions.
- Goal: preserve exact real payloads and reject unsupported operations explicitly.
- Non-goal: new fake techniques, dependency changes, root activation, device or
  external-network acceptance, and unrelated audit hypotheses.

## Decisions

- Check group activation before entropy preparation. Keep unknown escape fallback
  semantics and replace the unsafe UTF-8 slice with a checked slice.
- Restore shared queued pages on every exit before MD5 and TTL cleanup.
- Track whether raw emission may have started before allowing stream fallback.
  Mark opaque fake-send errors as possibly committed in the runtime. Keep exact
  byte counts separate and disable replay conservatively when progress is unknown.
- Resolve the genuine TTL from configuration or the live socket. Pass decoy MD5
  only to fake packet builders. Keep requested original flag overrides.
- Keep the checked conversion of sequence offsets, then use modulo addition.
- Keep version-three JSON encoding. Add command-specific bulk request admission
  and preflight limits. Keep generic control frame APIs at 8192 bytes. Bound bulk
  requests to one MiB, individual payload spans to 65535 bytes, aggregate payload
  to 196605 bytes, and ordered segments to 64. Reject invalid bounds before
  dispatch. A legacy helper without the advertisement cannot accept bulk traffic.
- Reject exact zero IPv4 Identification on IP_HDRINCL before emission. A new
  link-layer sender or a change to DF and MTU behavior is outside this repair.

## Contracts and ownership

- No Kotlin modules, JNI payloads, protobuf schemas, or stored settings change.
- The activation/parser/arithmetic lane owns F1/F5/F6. The send-safety lane owns
  F2/F3/F4/F8. The helper lane owns F7 and all helper version constants.
- The coordinator owns portfolio/OpenSpec state, API snapshot regeneration,
  architecture reports, combined gates, review, integration, and push.
- No Cargo.lock, dependency manifest, locale set, or golden fixture changes.
- The runtime possible-commit error state is an internal cross-crate contract.
  Helper preflight limits are additive. Existing byte-array encoding remains.

## Risks / Trade-offs

- Opaque pre-emission failures can also disable replay. This is safer than
  replaying a request whose first transmission cannot be excluded.
- The bounded bulk receiver can allocate up to one MiB before it identifies a
  nonbulk command. Command validation still rejects a nonbulk frame over 8192.
- macOS cannot execute Linux socket paths. Use owning Linux tests where a local
  nonprivileged Linux test environment is available; report any unexecuted path.
- API snapshots must be regenerated by the owning command. No baseline is raised
  to hide a regression. Independent reviewers inspect behavior and unsafe code.

## Migration Plan

There is no stored-data migration. The client checks additive helper limits
before it sends a large command. Old helpers retain control-sized operations.
Exact zero IPv4 ID requests now fail explicitly on the unsupported backend.
Rollback reverts the individual fix commits; no history rewrite is required.

Validation starts with each owning crate's tests and clippy. Combined validation
includes affected Rust tests, Linux-target compile coverage, `just ci-gates`,
`python3 scripts/ci/check_architecture_health.py`, and locked Cargo metadata.
Root, physical-device, external-server, signing, and deployment actions are not
part of this change.
