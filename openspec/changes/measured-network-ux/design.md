## Context

The approved research defines seven sequential feature slices. Existing RDS controls, diagnostic path enums, telemetry, profile stores, export redactors and protected payload URL-tests provide the base. Discovery found missing scan explanations, technical path enum display, unused health timestamps, saved-setting facets presented as active, absent picker search, direct export launch, and no durable timed pause.

## Goals / Non-Goals

- Goal: deliver all seven behaviors with factual source-derived UI and explicit failure states.
- Goal: retain Android offline/non-root operation and user-controlled exports.
- Non-goal: geography maps, synthetic scores, fabricated router measurements, commercial subscriptions or a new backend.

## Decisions

- Preserve RAW_PATH/IN_PATH as machine data; localize presentation and explain the actual direct-path interruption of VPN or proxy without unconditional restoration promises. Manual restoration follows the auto-resume setting (enabled in app defaults); strategy trials are isolated measurements. In-path admission on Android requires a running RIPDPI runtime; VPN mode additionally requires an eligible active route lease and proxy mode checks its local listener against the planned endpoint.
- Publish measurement timestamps/windows from the owning service DTO. Do not reuse the five-minute connection-health window for cumulative DNS/latency aggregates.
- Capture an immutable applied configuration summary in service ownership when the runtime starts; compare saved settings to the applied summary. Do not infer applied config from a UI observation of Connected.
- Reuse diagnostic family grouping and existing relay types. Search is local/saveable; filtering or closing never changes selection.
- Prepare immutable actual export content before external launch for diagnostic summary/archive, Home analysis, and Settings/Logs exports. Preview the final archive summary.txt, actual inventory and byte size from the prepared ZIP; text-only logs retain their actual text/plain contract. Apply typed redaction before summary projection and capture external runtime context once. Preserve schema 12 and the fixed redacted_unlinkable_v2 policy. Confirmation consumes one prepared generation and SAF copies its exact bytes, without reloading Room. Cancel, replacement and late preparation results discard only their owned artifact and ExportRecord under archiveMutex, preserving cancellation and reporting cleanup errors. Keep normal committed-archive DATABASE recovery intact. Checked app-private managed leases survive recreation/process restart, exclude unexpired artifacts from count retention, and expire no later than the existing three-day maximum using same-boot elapsed time as well as wall-clock checkpoints. Detected backward wall-clock changes, changed boot identity or unavailable clock proof invalidate the old lease; a fresh export can be prepared when the clock proof is available. The private journal preserves the latest clock checkpoints across concurrent phase writes. The read-only FileProvider revalidates confirmed lease identity, expiry, actual bytes and archive integrity without initializing Room or Hilt; chooser launch retains eligible files for delayed URI reads.
- Implement durable pause using persisted generation/mode/deadline and service-owned scheduling/reconstruction. Retain the existing specialUse foreground service with a paused notification while releasing native runtime/TUN, and use permissionless setAndAllowWhileIdle alarm delivery plus sticky reconstruction. State that Android may delay idle delivery; never promise exact wakeup. Confirm shell teardown/boot ownership before slice six edits. An activity coroutine or unbounded delayed worker is insufficient. Android references: https://developer.android.com/reference/android/app/Service#START_STICKY and https://developer.android.com/reference/android/app/AlarmManager#setAndAllowWhileIdle(int,long,android.app.PendingIntent).
- Pause resumes the chosen mode using current saved settings, with this effect stated in the UI. Ordinary saved configuration/profile edits retain the pending pause. Explicit Start/Stop, profile activation/deletion and reset supersede it. Persist the typed pause intent before teardown; a persistence failure keeps the active connection. Reconstruct a paused foreground shell without native/TUN/selector/probe activity. Clear the consumed pause only after positive runtime applied acknowledgement; denied consent, stale intent, cleanup failure and delayed OS delivery remain factual states. A stale deadline callback cannot restart a newer user intent. Boot handling must honor OS eligibility and show deferred/unavailable recovery honestly.
- A mandatory checked `PauseIntentAuthority` in `:core:data:runtime-state` owns persistent generation/token/mode/deadline/boot/phase and atomic matching transitions. Process-local service arbiters remain queue fences. Service/profile mutexes may call a short authority operation; authority never calls back into service/data or holds its lock across dispatch, native cleanup, DataStore mutation or journal replay. Explicit commands persist their intent before dispatch and revalidate after suspension.
- Generation identifies a user intent, so its own matching applied ACK consumes the pending pause token without allocating a different intent generation. New superseding commands advance generation. Later runtime guards recognize the captured successful attempt; duplicate consumed alarms, resume intents and ACKs cannot create another runtime or tear down that successful runtime. A later Stop or Pause still supersedes it.
- A separate singleton `RuntimeIntentLinearizer` serializes every authority mutation with final runtime publication. Complete durable applied ACK first, then redeem a typed generation/mode permit under the shared gate for registry insertion and pure in-memory Connected/status publication only. Release the authority state lock before publication; preserve Store/data/arbiter to linearizer to state-lock order and never enter Store, data, arbiter, tracker, native or suspend work from the publication action. Monitoring, telemetry and watchdog run after the gate. A Stop committed after ACK but before final publication prevents obsolete Running; a matching successful ACK retains its generation.
- Authority also persists desired Running/Stopped/Paused state and chosen mode. A failed old boot-session marker write cannot resurrect a durable Stop through sticky, process-death or package-update recovery. The one-way legacy Unknown state preserves user pointers but never fabricates Running ownership.
- Profile mutations receive a required typed origin with no default: saved edit, import-only, subscription refresh, bootstrap, internal reconcile and compensation retain pause; explicit activation/deletion/reset/profile restore supersede. Journal v2 persists origin, mutation ID and the expected authority reference before after-image replay. Invalidation is checked and idempotent by mutation ID and expected generation; old recovery preserves a newer intent. Explicit Reset reserves a checked durable Stopped receipt before clearing its journal or writing data, without replaying a corrupt marker. Strictly missing authority is initialized by that same single Stop commit; read/decode failure is never treated as absence. Existing generations remain monotonic. A failed Stop preserves journal/data; a failed clear keeps Stopped and skips destructive replay. Rollback never restores a previous pause.
- Mutation invalidation returns a reserved captured receipt, a non-superseding outcome, or a newer-intent outcome. Explicit activation dispatch requires the reserved receipt; reading current generation after replay cannot manufacture ownership. Suspend user-command preparation performs recovery and durable reservation, then releases the data mutex. Synchronous framework dispatch validates the captured durable/local lease and stamps the Intent; the service validates both again before and after native startup. Internal diagnostics/boot/process recovery uses its captured authority without reserving a later user intent. Composite reset/restore owns one outer receipt and never recursively acquires the recovery mutex.
- Journal v1 conversion is a one-way data migration, not a second normal runtime contract. Complete its exact old replay only while pause authority is still uninitialized, then commit the migration boundary before any command can initialize authority. Coordinate this with the existing recovery mutex and mandatory recovery access. A v1 record coexisting with initialized authority is preserved and reported as inconsistent rather than guessing provenance or deleting user data. New mutations write only v2; malformed/missing required fields fail closed.
- Runtime stop returns separate disposition and cleanup outcome: stop service or retain a matching paused shell, and fully released, superseded or cleanup pending. Only confirmed full release of native runtime/TUN/protect/selector/probes/telemetry permits phase Paused. Build active session components lazily so sticky paused reconstruction creates no native resources. The paused shell remains truthful during deferred delivery, denied consent and cleanup failure.
- Preserve the standing Start-on-boot preference: only an actual unlocked BOOT_COMPLETED with the saved preference enabled and valid profile/consent/lockdown eligibility may authorize a distinct system boot-policy start. Capture the full authority snapshot before suspension; a checked CAS may replace an older Stopped/legacy Unknown intent, advances the common generation and returns its typed receipt. A newer Stop/Pause rejects that old snapshot or dispatch. Any pending pause takes priority and is reconstructed/deferred without native startup. Package-update, sticky and process-death recovery instead require captured durable Running; they cannot promote the old marker into authority.
- Resume completion requires a positive accepted applied-runtime acknowledgement and a mandatory durable consumer that clears only the matching pause lease. Rejected/stale acknowledgement or failed durable commit fails startup and cleans the runtime; it does not publish successful resume. Alarm PendingIntent identity includes generation/token in action/data. An alarm with no registered eligible foreground owner only marks due/deferred; it cannot claim a new foreground-start exemption. Boot component enablement accounts for a pending pause separately from the user's start-on-boot preference, while respecting credential unlock, OS eligibility, user-requested stop and current VPN consent/lockdown.
- Favorite/recent metadata is separate from secret-bearing profile configurations. Record successfully used recents only from positive runtime applied acknowledgement, with guaranteed publication and the mandatory durable consumer introduced together. Saved selection, pending activation and failed probes do not count. Use typed relay IDs or selector group/member ID pairs, reactive committed catalog generations, and prune references on deletion/reset.
- The runtime persistence owner commits matching pause completion and bounded successful-use history together, as one composite durable state. Its applied acknowledgement identity contains runtime ID, revision and mode; repeated identical acknowledgements are idempotent, conflicting payloads are rejected, and recent ordering uses a monotonic sequence. A failed commit changes neither pause authority nor recents and prevents successful runtime publication. Migration preserves the existing pause generation and pending intent. Favorites remain private metadata; raw network identifiers are never persisted here.
- Activation uses a persisted command identity, typed origin and bound mode. Start-capable receipts are distinct from Stop/Reset receipts. Explicit profile activation may confirm Running from its own reserved Stopped state only after its exact per-attempt claim and positive acknowledgement. Bind before framework dispatch, claim before native startup, terminate on failure, and consume on matching acknowledgement; only an identical completed acknowledgement is idempotent. Generation alone, an action string, or a freshly read authority cannot grant activation rights. The Intent carries the captured command envelope and the service validates it against durable state. Composite schema 3 migration retains counters, pending pause and history, and grants no activation capability to older records whose origin is unknown.
- Each runtime attempt retains its own activation, continuation, resume or recovery authority. A manual selector change carries the original activation receipt into that attempt; automatic selection, DNS refresh and handover remain continuations and do not add recent-use entries. A process-local selection receipt is not replayed by a newly attached collector. Persist one explicit active selector group ID; selecting a standalone native/Xray profile clears it, and inactive group changes do not reload the active runtime. Any one-time migration from the former first-group heuristic is persisted rather than recomputed on each start.
- Expose the existing measured URL-test selector capability, including visible/configurable probe URL, actual member latency and observation time; label it lowest measured HTTP response time. Retain existing scope/revision fencing and protected candidate cleanup. Unsupported/all-failed results preserve the current valid selection.
- A candidate measurement uses an ephemeral protected native relay and complete successful HTTP response, with bounded readiness, request and cleanup deadlines. Check measures without selecting; Check and select additionally requires an unchanged committed group, policy, network and runtime revision. Cancellation is propagated and incomplete cleanup is visible. Probe failures never create successful-use history, and switch timestamps come only from accepted runtime acknowledgement.
- Remove synthetic active-profile/failover assertions in the touched selector UI: require exact profile ID match and actual event evidence.

## Measured-selection reservation and crash boundaries

A measured selection validates its captured profile payload, catalog, network epoch, runtime and durable command under the recovery mutex before reserving the exact ExplicitActivation command. The linearizer segment remains synchronous and contains no DAO, suspension, framework dispatch or native work. Its compare-and-set uses the originally captured authority/catalog and a current in-memory epoch predicate. This measured-only path reserves before journal preparation; ordinary mutations retain their established prepare-before-reserve order.

The journal preserves that same reserved command ID, origin and authority instead of granting another capability during replay. A crash between reservation and preparation leaves truthful Stopped/Unbound state without dispatch or history. After preparation, recovery may finish stored selection/catalog persistence, but it must not mint, bind or dispatch activation, or record usage from a lost transient measurement. Activation after reconstruction requires a new explicit user action. No raw network scope is persisted.

Preparation or persistence failure cancels only the exact owned pending/unbound reservation and preserves the original error; compensation cannot roll back a newer command. Binding/claiming revalidates the transient measurement lease, and positive ACK remains fenced by the captured payload/catalog/network/runtime scope. Tests exercise both crash boundaries, failed prepare/commit, a newer Stop and changed measurement scope.


## Physical path fence for measured activation

The single process-owned candidate network observer tracks physical INTERNET + NOT_VPN callbacks rather than the app's default network or the VPN binder's initialization epoch. A redacted transient token fixes registration generation, monotonic event epoch, selected Network identity and defensive physical fingerprint. It is available only after the current registration supplies complete capabilities/link properties and a usable, unblocked, nonsuspended path. Stale registration callbacks cannot initialize or mutate it; returning from A to B to A cannot revive an old token.

Use the existing best-matching callback pattern on API 31 and later, and passive matching callbacks with sticky selection on API 27–30. The older fallback conservatively invalidates on any matching physical candidate event. There is no active network request or per-check observer. VALIDATED and CAPTIVE_PORTAL are fingerprint evidence, not prerequisites for an explicit local/LAN HTTP check; actual complete HTTP response determines measurement success.

Measurement completion, reservation CAS, bind/claim and positive ACK all compare the original physical token. Only the exact measured command context permits its own command/catalog/runtime changes and immutable expected after-image. The process-local registry proof is retired on ACK, rejection, cancellation, failure, Stop or supersession. Process reconstruction cannot reuse it. This observer proves physical-state stability and does not attest that the probe socket was bound to the observed Network.


## Exact measured configuration and consumption proof

A successful native/selector measurement carries a private process-local HMAC identity of the exact resolved configuration passed to native start. Normalize only service-owned local SOCKS host/port and socket-protection differences; all profile, secret-derived, TLS, QUIC, experiment and transient helper launch inputs remain significant. Raw material and identity are never persisted, logged or exported.

Before dispatch, registry binding captures the full immutable post-selection requested configuration outside recovery/authority/store locks. Its identity includes frozen TLS defaults, canonical experiment flags and QUIC resolution inputs. The production resolver uses these captured inputs. Consumer binding compares the attempt's captured requested identity synchronously before claim/native work; positive ACK separately compares the measurement identity with the exact consumed native configuration from readiness evidence before history or durable confirmation. Missing measured-origin proof fails closed. The public applied/history storage schema stays unchanged.

Mode replacement, rejection, cancellation, failure, Stop and success retire the exact process-local proof. A different configuration captured or consumed between settings A to B to A is rejected; an intermediate edit that never becomes requested or consumed input does not require a global policy counter. Physical callback ABA still advances the separate network epoch. Dynamic resolver outputs are frozen when they contribute to measurement authority, or rejected conservatively; they are not broadly normalized.
