## Purpose

Make settings and Simple actions clear, preserve accessible navigation at large
fonts, and keep locale export evidence consistent with the application source.

## ADDED Requirements

### Requirement: REQ-UI3-SETTINGS — Group settings by user task

The app MUST group settings as Connection, Interface, Privacy and Support.
Language MUST be in Interface and show the selected native language or system
selection. Navigation-only rows MUST retain a clear action without a repeated
Manage value. Existing permission repairs, security warnings, advanced persona
controls and backup functions MUST remain reachable. Values MUST NOT invent
profile counts or state that the available model does not supply.

#### Scenario: Read settings and open a destination

- **WHEN** the user opens settings in either persona
- **THEN** the four groups and truthful values explain the available controls
- **AND** each existing destination and permission repair remains available

### Requirement: REQ-UI3-SIMPLE — Explain diagnostic effects

Simple MUST label the diagnostic action as checking and configuring the
connection. Before launch it MUST state that DNS, bypass strategy and WARP may
be saved automatically. It MUST show actual applied-settings evidence when
available. Failure, cancellation or an absent outcome MUST NOT imply no changes.
Existing pending, permission, disabled-action and cancellation behavior MUST
remain. The change MUST NOT alter the diagnostics apply contract.

#### Scenario: Analysis applies settings before a later cancellation

- **WHEN** analysis is cancelled or fails after it may have saved settings
- **THEN** the UI states that saved changes may remain
- **AND** it shows actual applied settings only from available outcome evidence

### Requirement: REQ-UI3-BACKUP — Expose truthful configuration restoration

Simple MUST offer the existing backup and restore UI before analysis and from
its result context. It MUST preserve export privacy, import preview and explicit
restore confirmation. It MUST NOT expose factory reset in this Simple surface.
Copy MUST explain that configuration restore does not erase network memories
and that Simple startup selects its bundled profile. It MUST NOT promise exact
Undo or restore settings from a SHARE bundle that contains no settings.

#### Scenario: Return from backup without exporting or restoring

- **WHEN** the user opens backup from Simple and presses Back
- **THEN** Simple returns to its prior screen without an automatic mutation
- **AND** Full backup/restore keeps its existing behavior by default

### Requirement: REQ-UI3-NAVIGATION — Keep fallback navigation compact

The app MUST preserve all four destination names, selection, order, callbacks,
focus behavior and stable IDs. At narrow large-font widths it MUST omit
decorative icons where needed and use natural-height text rows with at least
48dp touch targets. It MUST NOT reduce the font or clip labels to gain space.
At 360dp/font2, when two columns fit, content height MUST be at most 112dp,
excluding system navigation insets. The normal four-column design stays intact.

#### Scenario: Navigate at font scale two

- **WHEN** all labels fit a two-column fallback at 360dp and font scale two
- **THEN** every destination is visible, selected state is clear and content
  height is at most 112dp with each touch target at least 48dp
- **AND** LTR and RTL actions select the same intended destinations

### Requirement: REQ-UI3-NEUTRAL — Separate waiting from problems

Unmeasured, partial and historical measurement states MUST use an information
symbol with existing neutral surfaces. Real Warning and Critical states MUST
retain warning treatment. Connection or transferred bytes MUST NOT imply a
successful quality measurement.

#### Scenario: Connected without quality samples

- **WHEN** the app has no sufficient current quality measurements
- **THEN** its message and symbol are neutral and its reprobe action remains

### Requirement: REQ-UI3-LOCALES — Keep resource and export contracts aligned

All new and changed resource keys MUST be present in all ten locales. The
translation manifest MUST be generated by its owning export script and pass
check-translation-export.sh. No quality gate or baseline may be weakened.

#### Scenario: A new translatable key is added

- **WHEN** the changed source resources are prepared for integration
- **THEN** their generated manifest and locale parity checks pass

### Requirement: REQ-UI3-ACCESS — Verify presentation without overstating proof

Changed actions MUST expose safe names, values and state to semantics. Light,
dark, 360dp and 2x-font layouts MUST keep actions reachable without clipping.
The verification record MUST separate source tests, renderer, emulator, hosted
CI and real-user or assistive-technology evidence. Secretless Simple fixtures
MUST NOT be presented as proof of a working remote connection.

#### Scenario: Inspect evidence before integration

- **WHEN** checks and captures are recorded
- **THEN** their exact source and scope are stated, including unverified speech,
  user comprehension, physical-device performance or real relay access
