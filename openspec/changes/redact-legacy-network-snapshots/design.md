# Design

Task ID: `DGN-1790436692670903`

The database module cannot depend on the `NetworkSnapshotModel` in `:core:diagnostics` without a module cycle. Migration 13→14 therefore parses each JSON payload in `:core:diagnostics-data` and applies the same field-level projection as the capture path. It validates required fields and types against the version 13 model and rejects unknown keys, including keys in nested path evidence. Valid rows preserve known coarse fields, timestamps, and row links. A parse failure or wrong shape removes only that snapshot row, so a malformed payload cannot retain raw values in an unknown field.

The migration reads IDs in bounded batches and updates or deletes rows after each read batch. Keyset paging by ID avoids skipping rows after deletion. Room runs the migration in its upgrade transaction. The schema version changes without changing table definitions; the version 14 JSON schema is generated by Room KSP. Nullable root fields can be absent because production JSON uses `explicitNulls=false`; the shape validator accepts their absence.

An upgrade test seeds a version 13 database, opens it through the production builder, and checks redacted Wi-Fi and cellular values, preserved counts and coarse fields, isolated malformed-row deletion, and preserved unrelated data. Public IP and ASN are excluded from this privacy decision and remain unchanged.
