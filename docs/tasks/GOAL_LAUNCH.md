# Goal Launch — running the RIPDPI task board with `/goal`

Generated by `scripts/goal-adapt.py`. This is the operator runbook for
driving `docs/tasks/issues/*.md` to completion with `/goal`. The core
constraint it is built around: **the `/goal` evaluator reads only the
transcript, not the repo** — so every claim it must judge is forced
into the transcript by the goal condition itself (the ledger `cat`,
per-task command output, exit codes).

## 0. One-time pre-flight (do this *before* the first `/goal`)

Run this as a normal prompt, not as a goal — so the loop's first turn
is a work turn, not a parse turn:

```
Read docs/tasks/GOAL_LEDGER.md and docs/tasks/issues/<first 5 slugs>.md.
Confirm: (a) the ledger row count matches `ls docs/tasks/issues/*.md`,
(b) each task file has a `## Goal contract` block with a Verify command,
(c) no row you are about to start is still `TODO(verify)` or
`TODO(scope)` — if any are, pin a real command/scope in the issue file
and re-run `python3 scripts/goal-adapt.py --apply`. Do not start
implementation.
```

Then **review the `TODO(verify)` / `TODO(scope)` counts** in the ledger
header. Those rows have a heuristic placeholder, not a real verification
command — pin them before they enter a phase, or the loop will mark
them BLOCKED.

## 1. Permissions + auto mode

`/goal` removes the per-*turn* prompt; auto mode removes the per-*tool*
prompt. You need both or the loop stalls on the first edit:

1. `/permissions` → allow at least: `Edit`, `Write`, `Bash(./gradlew*)`,
   `Bash(cargo*)`, `Bash(just*)`, `Bash(git*)`, `Bash(cat*)`.
2. Turn **auto mode on**.

(`Phase` column). Phases respect topological order, so running them in
sequence keeps every `Blocked-by` satisfied. Run one phase per `/goal`;
the goal clears on success so you can chain them. Between phases run:

```
/compact focus on GOAL_LEDGER.md state, the last phase's BLOCKED rows and why
```

## 3. The `/goal` command (one per phase)

Substitute `{A}` and `{B}` with the phase's first/last ledger row
numbers from the table above.

```
/goal Work through docs/tasks/GOAL_LEDGER.md rows {A}-{B} in listed order. For each row: open docs/tasks/issues/<slug>.md and read its `## Goal contract`. If any Blocked-by slug is not already DONE in the ledger, set the row to BLOCKED (unmet dependency) and continue. Otherwise implement the task per its file using TDD — write the failing tests named in its `## TDD workflow` / `## Test plan` first, confirm they fail, then the minimal code to pass. Then: (1) run the contract's Verify command and paste its full output + exit code into the transcript; (2) set the issue file's canonical line to [x] + #status/done on pass, or #status/blocked + a one-line reason on fail; (3) update the <slug> row in docs/tasks/GOAL_LEDGER.md — Status = DONE or BLOCKED, Proof = the Verify command + exit code; (4) cat docs/tasks/GOAL_LEDGER.md so its state is in the transcript. Constraints: only modify files inside each task's Scope plus its own issue file and the ledger; do not skip rows; if a Verify fails twice in a row mark the row BLOCKED with the failure reason and continue. Goal achieved when every row {A}-{B} is DONE or BLOCKED in GOAL_LEDGER.md, `./gradlew :app:assembleDebug` exits 0, and `./gradlew test` exits 0 — with the ledger cat, the assembleDebug output, and the test output all visible in the transcript. Stop after 60 turns.
```

## 4. Why this satisfies the transcript-only evaluator

- **Ledger forced into the transcript** — step (4) `cat`s it every task.
- **Verification run, not claimed** — step (1) pastes real output + exit code.
- **Hard turn cap** — `Stop after 60 turns` guarantees termination even
  if the condition never flips.
- **Auto mode on** — no per-tool prompt stalls the unattended loop.
- **Scope fenced per task** — the contract's Scope line makes "do not
  modify files outside scope" enforceable.

## 5. When `/goal` is the wrong tool here

- **Mostly-independent tasks** → `/batch` instead: one background
  subagent per task in an isolated worktree, one PR each. Better for the
  many leaf tasks with no dependents than a serial loop.
- **Hard human gates between phases** → `/plan` per phase, skip `/goal`.
- **Scheduled re-runs rather than until-done** → `/loop`.
