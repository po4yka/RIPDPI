## Objective

Show the selected relay on Status after a relay failure

## Ownership

One writer in worktree `route-after-relay-failure-fad509` owns the Status actuator label (`MainStateResolvers.kt`, `ActuatorEgressHonesty.kt`), the Connection relay rows (`ConnectionScreen.kt`), and their tests. No strings, goldens, or service code change.

## Execution

- [x] UIX-1795615862157566 Define implementation and verification #bug @item:UIX-1795615862148383

## Findings

- On main, a relay that fails to start leaves the session in `Error`. `FailedSwitchRestorer` only restarts a previous session that was running, and `StatusConnectedServer` appears only while connected. The actuator named an exit only for an AmneziaWG profile or a subscription member, so a failed manual relay read `Direct` with the bypass strategy.
- The `Relay server`, protocol, and credentials rows called `onEditCurrent`, which opened the selected preset in the Manual editor.

## Change

- While no session carries traffic, the actuator names the selected relay server (`<server> · <kind>`, as in the server list) and hides the bypass strategy. A connected session keeps the telemetry-based label, so a relay that drops mid-session still reads `Direct` (audit P1-1).
- The relay rows open the selected server through `ConnectionProfileActions.edit`; `onEditCurrent` is removed.
