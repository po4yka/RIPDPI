## Highest-leverage findings

- **SOCKS5 UDP ASSOCIATE exists and is on by default — the docs said it does not exist.** Implemented in two independent paths. _(2026-06-01: the app can now disable it via proto `udp_associate_enabled`; §1 re-verified — datapath full, zero code gaps.)_
- **Mixed inbound (SOCKS4 + SOCKS5 + HTTP CONNECT on one port) is implemented and undocumented.** First-byte peek dispatches; SOCKS4 inbound is wholly undeclared (§7).
- **VMess, Trojan-Go, and Hysteria v1 were removed entirely** (code + docs) per [ADR 0004](../adr/0004-protocol-support-policy.md) — they were never-completed stubs that carried no traffic. Mieru, SSH, and AnyTLS now have live registered backends; their transport capabilities are listed in §10.
- **The Xray provider (VLESS/REALITY/XHTTP) is a Go/gomobile path, not Rust**; its `.so` is not committed and its REALITY ECH behavior is opaque to the Kotlin/Rust layers (§11).
- **VLESS REALITY ECH-GREASE parity is implemented in code but defaults Off.** `reality_ech_parity()` (`ripdpi-tls-profiles`) gates BoringSSL `set_enable_ech_grease(true)` on fingerprint-profile + cover-domain ECH evidence; the connect path wires it (`ripdpi-vless/src/reality.rs:67`) but passes `CoverEchEvidence::Unknown`, which resolves to `RealityEchParity::Off` — so the live ClientHello still emits no ECH extension. Real ECH remains unused per ADR 0001 (§5b).
- **DoQ is silently blocked over SOCKS5 transport**, which is the transport the proxy runtime uses internally; the new DoH-JSON survey is **diagnostics-only** and never a runtime resolver path (§4).
- **Entropy padding is configured end-to-end *and applied*** (2026-06-01 correction): the generators run in `ripdpi-desync-runtime` (`tcp.rs:36` / `fake_burst.rs`) before planning — the 2026-05-31 "never applied" claim was a matrix self-error that searched `ripdpi-desync/src/fake.rs`, the wrong layer (§5).
- **`md5sig` is now enableable from the Android app** (root-gated Advanced Settings toggle; proto `fake_md5sig = 331`; mapper gate `fakeMd5Sig && rootModeEnabled`; degrades gracefully on non-root). **`tlsminor` is now exposed too** (2026-06-01): an enable toggle + 0–255 numeric input in Advanced Settings, proto `tls_minor_enabled = 332` / `tls_minor_value = 333`, plumbed through codec + adapter to `DesyncActions::tlsminor`. No root needed (§5, §6).
